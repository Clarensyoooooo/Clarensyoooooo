## About

I build practical systems end-to-end - from the database schema, to the deployed product, to the dashboard that explains it.

During a 500-hour internship I built a building-supply company's first sales platform, replacing an entirely spreadsheet-based workflow. It now runs **₱1M+ in monthly sales operations**, and management reporting went from a week of cross-department spreadsheet compilation to on-demand dashboards. I later re-architected it as a React + TypeScript SPA on Supabase, writing the MySQL to PostgreSQL migration myself so no production records were lost.

Before that, as sole developer under a memorandum of agreement with the City of Sto. Tomas, I designed and turned over a client management and analytics portal for the Persons with Disability Affairs Office - constituent records, appointments, and a GIS module mapping all 30 barangays.

BS Information Technology, Major in Business Analytics - Batangas State University, Class of 2026. Google-certified in Analytics and Ads Measurement.

## Featured Work

| Project | What it does | Stack |
|---|---|---|
| **[NAM Sales & Inventory Platform](https://github.com/clarenceneilmeneses/nam-refactored)** | A building-supply company's first real system: quotations, sales, inventory, finance, and logistics in one place, now used daily to run ₱1M+ in monthly sales. Executive BI views with cross-filtering drilldowns, and a unit-tested pricing and margin engine so dashboard figures reconcile with finance. Originally shipped in PHP ([sales_dashboard](https://github.com/clarenceneilmeneses/sales_dashboard)), then re-architected on Postgres. | React · TypeScript · Supabase · PostgreSQL · Vitest |
| **[PDAO Client Management & Analytics Portal](https://github.com/clarenceneilmeneses/pwd-portal)** | Government constituent-services portal for a city PWD affairs office serving ~4,000 registered residents: ID applications and renewals, appointment booking with slot management, and application tracking. Includes a GIS module that maps records across 30 barangays with custom point-in-polygon matching. Built and demoed entirely on synthetic data, so development never touched real constituent records. | PHP · MySQL · JavaScript · Leaflet · GIS |
| **[PapaFix Admin Panel](https://github.com/clarenceneilmeneses/papafix)** | The operations console for an on-demand home-repair marketplace - live technician tracking on a map, booking and payment oversight, and analytics that cross-filter on click. Aggregation runs in PostgreSQL functions rather than the browser, and an append-only audit trail is enforced by database triggers under row-level security. | React · Vite · Supabase · PostgreSQL · Leaflet · Recharts |
| **[Portfolio & CMS](https://github.com/clarenceneilmeneses/advanced-portfolio)** | My portfolio, rebuilt as a content-managed site - every section is editable from a private admin panel without a redeploy. Survives free-tier database cold starts via a keep-alive cron, ISR caching, and a bundled fallback snapshot. [Live](https://clarenceneilmeneses.vercel.app/) | Next.js · React · Supabase · Tailwind CSS |
